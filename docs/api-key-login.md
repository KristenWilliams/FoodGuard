# API Key 登录与本地历史

## 当前流程

1. 在设置中填写 HTTPS OpenAI 兼容接口地址与对应 Key，不必使用项目运营者的地址和 Key。根地址自动补 `/v1`，已有 `/v1` 或 `/openai/v1` 等路径会保留。
2. 点击“拉取模型”，获取该上游当前允许这个 Key 使用的模型。可在登录前选择快速与深度模型，点击旁边的测试按钮进行短文本连通测试。
3. 点击“登录”或“保存并测试”，应用再次校验模型并测试快速模型，成功后才替换本机配置。候选地址或 Key 失败，不覆盖原来可用的配置。更换地址须同时填写它对应的 Key；分析进行中不能更换配置或退出。
4. 登录后可以刷新模型、分别更换快速与深度模型并测试。默认优先匹配 `gpt-6-luna` 和 `gpt-6.1-sol`；不在上游列表中时使用列表中的模型，不假定所有上游都有这些模型。分析和小助理均使用用户选择的上游及自己的 Key。
5. 模型测试只证明文本请求可用，不证明它支持图片、响应速度或食品识别质量。测试也可能消耗少量上游额度。接口须支持 `/models`、`/chat/completions`；分析模型须支持图片输入和 JSON 输出。

仅接受公开 HTTPS 地址，不接受 HTTP、内网、回环、保留地址、带账号密码或查询参数的地址。后端检查 DNS 后锁定已验证地址进行 HTTPS 请求，保留证书校验，不跟随重定向，避免把 Key 发送到跳转网站。FoodGuard 自身域名不能作为上游。自定义上游请求仍经过 FoodGuard 服务，不是手机直连上游。

这不是账号注册系统。有效 Key 表示调用权限，不等于用户身份；余额、额度、到期、撤销和模型权限由上游管理。应用没有实现售卖、支付或开票系统。Key 发给朋友时应单独发送个人限额 Key，不要把公共 Key 打包进 APK。

## 隐私边界

- Android Key 和接口地址一起通过 Android Keystore 的 AES-GCM 加密保存；加密文件及任务文件在应用私有、不可备份目录中。
- 浏览器开发预览仅在会话存储中保存地址和 Key。关闭会话后需要重新登录。不向 localStorage 写 Key。
- 请求使用 HTTPS，将 Key 临时交给 FoodGuard 转发至用户配置的上游。后端不把用户 Key、图片、报告或聊天内容写入文件、数据库或日志；只在处理请求时使用。模型列表缓存以地址和 Key 的联合哈希区分，只含模型 ID，过期时间一分钟；手动刷新会绕过缓存。
- 历史最多 20 条，保存在手机本机。小助理仅在回答时临时接收本机报告摘要；服务器不留聊天历史，也没有查询其他用户历史的接口。
- 上游 AI 必然收到图片或报告摘要；上游自己的留存政策由其运营者决定，FoodGuard 不能保证上游零留存。
- 上述不存档约定指 FoodGuard 应用后端，不代表现有反向代理没有上传临时缓冲或访问日志。本次没有改动 Nginx；如需整条链路的零落盘，需要另行检查代理和上游设置。
- 换手机、清除应用数据或卸载会丢失本机历史。退出 Key 不删除历史。安装覆盖升级保留本机历史。
- 老 Supabase 数据库与迁移文件只保留作旧实现记录，不自动删除既有数据库。前端不再访问它；保留的旧函数源码返回 410。本次不连接、迁移或删除任何既有 Supabase 服务。

## 稳定性与后台

- 本机缓存按图片哈希、地址、Key 哈希、模式、模型、地区、语言及规则版本区分，最长七天、最多 20 项。读取时剔除过期、未来时间、格式错误和旧规则缓存。重复图片使用有效缓存，不重复请求上游；模型、上游或地区更改会重新分析。
- 设置中的“清理缓存”仅清理分析缓存，保留全部本机历史、登录配置和偏好。没有“清理全部本地数据”按钮。删除单条历史时同时失效对应缓存；“重新快速分析/重新深度分析”在确认可能计费后绕过缓存。
- 快速和深度模式都要求完整识别可读配料，不再截断为前几项；不同之处是解释详细程度和单次等待期限。不能读清的数据明确标为缺失、模糊或未知，不捏造营养值或参考占比；缓存保证有效期内重复请求复用已有结果，不保证不同模型或重新分析完全相同。
- 连接状态分别检测 FoodGuard 服务和选中的 AI 模型。离线、未配置、待测试、模型不可用、Key 错误会分开显示；模型变更或应用重启后不会把旧成功测试当作新连接证明。
- 同时在途的相同请求可共用一个上游调用。后端不保存完成结果，也不做跨设备历史同步。
- Android 使用 WorkManager 与前台分析通知。切换页面或正常切到别的应用时可继续；完成结果先加密落在本机，回到应用后幂等写入历史。
- 系统强制停止、省电限制、网络中断、重启和厂家后台管理仍可能中止分析。请求发送前在本机加密记录已发送状态，系统重启任务时不会自动重复这次付费请求；提示用户手动重试。不能承诺强制停止后仍继续运行。
- 快速、深度分析单次上游图像请求期限为 80/170 秒，包含读取响应；上传和模型列表获取另有期限。不再分别先做一次深度预检。浏览器超时真正 Abort，请求不在客户端无期限挂起。
- 长分析响应每 15 秒发送合法 JSON 空白保活，响应关闭 Nginx 缓冲，不修改站点配置。保活发出后 HTTP 状态已固定，调用者还必须检查最终 JSON 的 `error`/`code`，不能仅凭 HTTP 200 判定成功。应用和 Android 后台任务均做此检查。保活不延长上述分析期限，也不能修复上游本身超时。

## 报告与小助理

- 中文和英文界面均包含配料、数量、类别、限量、来源和营养图表标签。新报告按分析时的语言生成；已保存报告显示它自己的评估地区，改变偏好不重新判定旧报告。旧报告没有地区记录时明确显示“未记录”，不默认为中国、不计算未知地区的参考占比。旧报告原文不会被自动付费翻译。
- 小助理只接收当前报告和本机最多 20 条历史的摘要，包括配料、风险提示、营养值与单位、识别状态、营养基准及参考来源 URL，不包含原照片或 Key。保留原有约 100KB 上下文预算；超过预算的历史仅保留 ID、日期、地区等元数据，并标注详情缺省，不拼接或截断 JSON，不假装读过被省略的内容。
- 小助理返回的历史 ID 在服务器和手机上都仅与此次提供的本机记录核对，用户可以点击打开对应本机报告。不存在、其他用户或已删除的记录不会打开；服务器没有用户历史查询接口。更换登录配置或退出后清空当前小助理对话，防止前一配置的延迟回答混入。
- 小助理不在每次回复后重复免责声明；应用已有统一注意事项。不确定信息仍须明确表达，不能为了简短而给出虚假确定结论。

## 自托管

后端只需 Node/Docker，不需要数据库。`.env.server.example` 仅指定上游地址和默认模型，不填写公共 Key。APK 只含 FoodGuard 后端 URL。

```powershell
$env:VITE_FOODGUARD_API_URL='https://foodguard.littlemelon.top'
npm run android:sync
cd android
.\gradlew.bat assembleDebug --no-daemon --console=plain
```

换为自己的域名时，同时用 `-PFOODGUARD_API_HOST=你的域名` 构建 Android。正式发布应使用自己的私有签名密钥及 release 构建；不得提交签名密钥、本地环境文件、私人测试图片或用户历史。开源前还应确认软件许可证和图像资产授权。

后端最多两个同时运行的付费请求，容器上限 384MB、0.5 CPU，日志轮转。现有 2GB VPS 是否能承载，应与其他服务合并计算；不会在服务器安装模型或数据库。
